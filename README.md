## "5x、20x"乘的到底是什么

Claude 的个人订阅分 Free、Pro 和 Max 三层。Max 名字里的 5x、20x，指的是相对 Pro 的用量倍数，而且官方明确说了，这个倍数按“单次会话”计算。

具体机制是两套限制并行：

- **5 小时会话额度**：滚动窗口，每 5 小时重置一次。Max 5x 是 Pro 的 5 倍，Max 20x 是 20 倍。
- **每周限额**：跨所有模型计算，在账号绑定的固定时间重置，不随你什么时候开始使用而变化。周限额是单独的另一组数字，并不按“20x 是 5x 的 4 倍”这样简单放大。

另外，Opus 这类高端模型有独立的周额度池。重度使用时，先见底的往往就是 Opus 这一格。

官方只公布倍数，不公布具体条数。有第三方按 Pro 约 45 条消息的 5 小时基准做过推算：5x 大约相当于每次会话 225 条，20x 大约 900 条。这是算出来的参考值，不是官方数字，实际能跑多少还要看模型选择和上下文长度。

## 除了额度，5x 和 20x 还有什么不一样？

没有了。这是这个问题最容易被过度解读的地方。

两档 Max 能用的模型完全相同：Opus 5（Max 的默认模型）、Sonnet 5（Pro 的默认模型）、Haiku 4.5，以及定位更高的 Fable 5.1。Fable 5.1 在两档 Max 上的规则也一样——最多计入周额度的 50%，超出部分走按量积分；而在 Pro 上，Fable 5.1 从第一条消息起就要用积分付费。

Claude Code 也是两档都包含，而且它和网页聊天、后台长任务共享同一个额度池。你在 Claude Code 里跑 agent 的消耗和聊天窗口的消耗，用的是同一口井。这也是为什么不少 Pro 用户撞周限，基本都是 Claude Code 干的。

所以 20x 多花的 100 美元，买到的只是余量。如果你从没在 5 小时窗口或周额度上碰过壁，这 100 美元什么也换不来。

## 哪一档适合你？五个问题自测

判断 5x 够不够，可以直接回答这五个问题，有两个“是”就基本指向 20x：

1. 你会同时跑不止一个 agent 会话吗？并行是消耗倍增器，信号最明确。
2. 你会让 agent 长时间无人值守地跑任务吗？一次 40 分钟的自主运行，消耗远超 40 分钟有人盯着的对话。
3. 你用 agent teams（多智能体协作）吗？按官方给过的参考数字，队友在 plan 模式下运行时，消耗大约是普通会话的 7 倍，因为每个队友都带着自己的上下文窗口。

5. 你在很大的代码仓库里工作，agent 动手前要读大量文件吗？上下文体积对消耗的影响比会话时长更大。

五个全“否”，5x 几乎肯定够用，一年省下 1200 美元。三个以上“是”，20x 就不算奢侈——你会反复撞 5x 的天花板，被打断损失的时间比差价更贵。

## 开通之前，这几件事值得知道

- **限额只是被抬高，没有被取消。** 滚动 5 小时窗口、周限额、Opus 独立周额度在每档上都存在。持续并行跑 Opus 的重度用户，20x 也可能撞周限。

- **升级按比例补差价。** 从低档升高档，按账单周期剩余天数比例收费；从年付 Pro 转 Max，如果年付剩余余额高于 Max 价格，差额会以账户抵扣金返还，前提是两次订阅的账单地址一致。
- **档位不影响模型质量。** 输出质量的问题是模型的问题，多买余量解决不了它。
- 每周限额的重置时间绑定账号，下次重置时间可以在 Settings > Usage 里查看。

## 常见问题

**20x 的用量是 5x 的四倍吗？**
单次会话上是。5x 是 Pro 的 5 倍，20x 是 20 倍，所以 20x 的单次会话余量是 5x 的 4 倍。但周限额不按同样倍数放大，是单独的另一组数字。

**5x 和 20x 可以互相切换吗？**
可以。Max 是月付订阅，随时换档，低档升高档按比例补差价。先跑一个月 5x 再决定，是成本最低的验证方式。

**Max 会移除速率限制吗？**
不会，只是抬高。三重限制（5 小时窗口、周限额、Opus 独立周额度）依然生效。

**Claude Code 的额度单算吗？**
不算。它和网页聊天、后台任务共享同一个额度池，都在 5 小时窗口和周限额两套规则下运行。
